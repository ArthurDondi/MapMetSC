# R_intermediary — frozen phenograph outputs

Phenograph clustering in this project runs through `Rphenoannoy`, which uses
**Annoy** (approximate nearest-neighbour search, C++) followed by
`igraph::cluster_louvain`. Neither step is bit-reproducible across `igraph`
versions, compilers or CPUs, so the **same seed and same input data can produce
different clusters on a different machine or container** — the same caveat the
`uwot`/UMAP documentation gives for `calculateUMAP`.

To make the published results reproducible everywhere, the outputs computed in
the reference (docker) environment are shipped as `.rds` files:

* **`02_QC_1.Rmd`** still clusters (as an illustrative heatmap) but excludes lost
  cells by loading a frozen **list of kept cells** and keeping those — it no
  longer excludes by (non-reproducible) cluster number.
* **`04_phenotyping.Rmd`** loads the frozen **k=30 cluster labels** instead of
  re-running `Rphenoannoy`.

## Files

| file | used by | contents |
|------|---------|----------|
| `kept_cells_AD.rds`    | `analysis_AD/02_QC_1.Rmd` | character vector of kept cell ids (post lost-cell exclusion) |
| `pg_clusters_AD.rds`   | `analysis_AD/04_phenotyping.Rmd` | named vector, cell id → k=30 cluster → `pg_clusters` |
| `kept_cells_PTBM.rds`  | `analysis/02_QC_1.Rmd` | character vector of kept cell ids (post lost-cell exclusion) |
| `pg_clusters_PTBM.rds` | `analysis/04_phenotyping.Rmd` | named vector, cell id → k=30 cluster (before GMM subclustering) |
| `celltype_order.csv`    | `analysis/04_phenotyping.Rmd`, `analysis/06.1_correlation_AD.Rmd` | `;`-separated `order;celltype`; sets the celltype display order |
| `celltype_order_AD.csv` | `analysis_AD/04_phenotyping.Rmd` | same, for the adrenal-gland (AD) reference cohort |

Cell ids are `sample_id_ObjectNumber`. With `pg_clusters_*` loaded, the manual
celltype annotation stays valid because the phenograph cluster numbers are
frozen.

The `celltype_order*.csv` files are static annotations (not generated by
`generate_phenograph_intermediary.R`); they are loaded from here with the same
directory search as the `.rds` files, falling back to `params$input` for older
data layouts.

## How to generate

The outputs already exist in the docker SPE objects (the columns of `spe_02` are
the kept cells; `pg_clusters_k30` lives in `spe_04`), so nothing is re-clustered.
Run once in the reference docker image (see
`code/generate_phenograph_intermediary.R`):

```sh
Rscript code/generate_phenograph_intermediary.R      # reads spe_*.rds, writes here
```

It reads:
* `colnames(spe_02_QC_1*.rds)` → `kept_cells_*.rds`
* `pg_clusters_k30` from `spe_04_phenotyping*.rds` → `pg_clusters_*.rds`

The load lookup order is `params$input/R_intermediary/` first, then
`params$output/R_intermediary/`. Ship the files next to the input data
(`params$input/R_intermediary/`) or download them from Zenodo alongside the
other `R_intermediary` objects.

> These `.rds` files are **not** committed here (they depend on the dataset).
> This folder and README document the scheme and give the loader a stable path.
